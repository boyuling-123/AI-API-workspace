# PR 05D 验收证据：少量试评与复用输出重新评价

## 视觉证据

- `evaluation-trial-confirm.png`：展示少量试评确认框、裁判调用数、被测模型零调用、历史输出复用数与“不写入”边界。

## 自动化路径

- `tests/unit/evaluationExecutionPlan.test.ts` 直接覆盖真实执行计划源文件的默认试评数量、最大上限、确定性取样、输入去重、正式范围和历史写入边界。
- `tests/e2e/evaluation-trial-rerun.spec.ts` 使用 Mock 覆盖 3 条跑批、2 条试评中 1 条解析失败、试评历史保持 0、同一批输出两次正式评价形成 2 条独立记录。
- E2E 精确断言被测模型只在首次跑批调用 3 次；后续试评和两轮正式评价只调用 `/api/evaluate`，被测模型调用总数不再增加。
- 确认弹窗通过 WCAG 2A/2AA/2.1A/2.1AA 严重与致命问题检查。

## 安全边界

- 试评与正式评价均需先展示调用预览并由用户确认，不会因进入页面自动调用 Judge。
- 试评最多 5 条，仅在当前页面展示成功评分和逐条错误，不创建 `EvaluationRecord`。
- 正式评价复用已完成的 Task 输入与输出，每次新增独立评价记录，不覆盖跑批结果或已有评价。
- 所有自动化请求均为 Mock，未读取真实密钥、未调用真实或付费模型。
