# 测评平台 v5.0 待补充功能清单

> 基于《测评平台 v5.0－数据集标注与多策略评价 PRD》及当前代码实现整理。
> 本清单用于补充功能和校准实现状态，不修改原 PRD。

## 一、优先校准文档状态

- [ ] 将功能状态统一拆分为：`已实现`、`部分实现`、`方案已设计`、`待开发`。
- [ ] 将 OpenJudge 评价维度生成从“已实现”调整为“方案已设计”。
- [ ] 明确当前维度生成仅基于用户评测需求和内部预设范例调用通用模型，尚未接入代表性样本、人工标注数据及 OpenJudge。
- [ ] 将七个 Skill、MCP 接入、Judge 校准和排行榜报告等未落地能力调整为“方案已设计”或“待开发”。
- [ ] 统一多人标注口径，解决“暂不支持多人标注一致性”与“已实现一致性检验”的文档冲突。
- [ ] 区分产品完整方案、当前 Demo 和当前代码能力，避免三种状态混写。

## 二、评价维度生成 Skill

- [ ] 建立 `evaluation-dimension-generator` Skill，并明确 OpenJudge 是其底层能力。
- [ ] 输入用户的评测目标、业务场景和任务类型。
- [ ] 从用户选定的测试集或已有跑批结果中抽取代表性输入输出样本。
- [ ] 支持输入标准答案、硬规则、Bad Case及人工评分或排序结果。
- [ ] 无人工标注时，使用 Simple Rubrics Generator 生成候选维度。
- [ ] 有人工评分或偏好排序时，使用 Iterative Rubrics Generator 生成并校准维度。
- [ ] 对候选维度进行字段标准化、同义合并、重复检测和冲突检测。
- [ ] 校验每个维度是否具有清晰定义、评分分级、证据要求和可执行判断条件。
- [ ] 允许用户增删、修改和确认维度，并设置权重及一票否决项。
- [ ] 将确认后的维度保存为版本化 Evaluator，并生成对应 Judge Prompt。

## 三、Judge Prompt 生命周期

- [ ] 根据已确认的维度、评分标准、证据要求和权重自动生成 Judge Prompt。
- [ ] 支持用户手动修改 Prompt。
- [ ] 支持使用少量样本试跑并预览评分结果。
- [ ] 保存 Prompt 版本、修改人、修改时间和适用任务。
- [ ] 支持新旧版本 Diff 对比。
- [ ] 支持历史版本恢复。
- [ ] Prompt 或维度发生变化后，支持重新校准 Judge。
- [ ] 复用原有模型跑批结果，仅重新执行评价，避免重复调用被测模型。

## 四、Judge 选择与校准

- [ ] 建立 Judge 候选池，记录厂商、模型、模态、上下文长度、成本和时延等信息。
- [ ] 根据文本、图片、代码等任务类型筛选合适的 Judge。
- [ ] 建立人工标注的黄金测试集。
- [ ] 对比 Judge 与人工判断的一致性、准确性和漏判情况。
- [ ] 支持单 Judge、多 Judge 独立评价和分歧仲裁。
- [ ] 对高风险结果和高频分歧 Case 保留人工复核入口。
- [ ] Judge、维度或 Prompt 变更后重新运行黄金测试集。
- [ ] 校准未通过时禁止直接发布新的 Evaluator 版本。

## 五、模型与能力候选池

- [ ] 建立模型／算法／Judge 统一资源池。
- [ ] 记录能力类型：文本理解、图片理解、文生图、图像编辑、视频生成、业务算法等。
- [ ] 记录支持的输入输出模态和参数范围。
- [ ] 记录接口来源、版本、别名和有效状态。
- [ ] 记录历史评测主题、维度表现、耗时、成本和失败率。
- [ ] 支持按任务要求筛选候选模型，而不是直接将完整排行榜交给 Agent。
- [ ] 支持主榜候选、专项候选和别名对照的分层管理。

## 六、大批量任务执行

- [ ] 将每条 Case × 模型任务拆分为独立子任务，单项失败不阻塞整批。
- [ ] 支持配置并发数和 QPS。
- [ ] 大批量任务采用分批提交、分批执行和逐批落库。
- [ ] 保存任务检查点，支持中断后续跑。
- [ ] 支持仅重跑失败项、指定 Case、新增模型或新增维度。
- [ ] 设置单任务超时和有限次数自动重试。
- [ ] 超过重试上限后标记明确的超时／失败类型，不再无限重试。
- [ ] 支持任务暂停、继续和人工终止。
- [ ] 支持预算预估、预算上限和超限暂停。
- [ ] 支持任务完成、失败率过高和预算异常等通知。

## 七、图片评测资产策略

- [ ] 原始图片统一保存，不因 Judge 评测而覆盖或替换。
- [ ] 仅在提交 Judge 的环节生成压缩副本，以控制 Token、带宽和成本。
- [ ] 结果页面、历史记录和导出报告继续展示原图。
- [ ] 记录原图与压缩评测副本的映射关系。
- [ ] 保存图片处理参数，保证评测过程可追溯。

## 八、报告与人工复核

- [ ] 输出模型综合排行榜和单维度排行榜。
- [ ] 支持用户勾选关注维度后动态重新排名。
- [ ] 支持查看每个模型、每条 Case、每个维度的评分和理由。
- [ ] 支持查看 Judge 引用的证据。
- [ ] 支持筛选低分、分歧、高风险和失败 Case。
- [ ] 支持人工修改评分、标记 Bad Case 和补充复核意见。
- [ ] 输出 HTML 报告，并保留原始结果、评价配置和版本信息。

## 九、CLI Agent 联动

- [ ] 在工作台内嵌终端窗口或提供终端联动入口。
- [ ] 支持连接 Claude Code、Codex 等本地 CLI Agent。
- [ ] 支持选择并编辑 `CLAUDE.md`、`AGENTS.md` 等系统指令文件。
- [ ] 支持预览最终加载的 System Prompt 和上下文来源。
- [ ] 支持将当前测试集、模型配置、评价规则和结果文件传递给 CLI Agent。
- [ ] 支持 CLI Agent 修改指定文件，但必须展示变更内容并由用户确认。
- [ ] 记录 Agent 执行日志、文件变更和运行结果。
- [ ] 明确终端执行权限、工作目录和可访问文件范围。

## 十、安全与密钥管理

- [ ] API Key 仅由服务端读取和注入。
- [ ] Key 不进入前端状态、浏览器缓存、导出文件和日志。
- [ ] Skill、Prompt 和报告中不保存真实 Key。
- [ ] 对敏感参数进行脱敏展示。
- [ ] 区分查看、运行、修改配置和发布 Evaluator 等权限。
- [ ] 记录接口配置、Prompt、Evaluator 和任务操作审计日志。

## 十一、建议实施顺序

### P0：先保证口径真实、任务可用

- [ ] 校准 PRD 中所有功能的实现状态。
- [ ] 完成分批落库、失败重跑、断点续跑和预算控制。
- [ ] 补齐 API Key 服务端管理和日志脱敏。
- [ ] 补齐 Judge Prompt 的编辑、试跑和版本管理。

### P1：完成评测方法闭环

- [ ] 正式接入 OpenJudge 维度生成能力。
- [ ] 接入代表性样本和人工标注数据。
- [ ] 完成 Judge 黄金集校准和分歧仲裁。
- [ ] 完成维度、Prompt、Judge 和 Evaluator 的统一版本管理。
- [ ] 完成多维排行榜、Case 下钻和人工复核。

### P2：扩展为可复用的评测节点

- [ ] 完善模型与 Judge 能力候选池。
- [ ] 将接口接入、跑批和评价能力封装为独立 Skill／MCP 能力。
- [ ] 接入本地 CLI Agent 和指令文件管理。
- [ ] 支持其他生成流程直接调用评测能力并回收结果。

## 十二、验收标准

- [ ] 文档中每项功能都有唯一且真实的实现状态。
- [ ] 同一批模型输出可以更换维度、Judge、权重或 Prompt 后重新评价，无需重跑被测模型。
- [ ] 大批量任务中断后可以从已完成进度继续执行。
- [ ] 单项失败不会导致整批任务失败，且错误原因可定位、可重跑。
- [ ] 每个评价结果都能追溯到测试集、模型版本、维度版本、Prompt 版本、Judge 和原始证据。
- [ ] 用户能够查看并修改 AI 生成的评价维度和 Prompt，最终配置必须经过人工确认。
- [ ] API Key 和敏感信息不会出现在前端、日志、导出结果或 Skill 文件中。
- [ ] 当前代码、演示页面和 PRD 描述保持一致，不再出现“方案能力被写成已实现”的情况。
