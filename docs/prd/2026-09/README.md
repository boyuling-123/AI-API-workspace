## 定位与路径

平台是产品经理使用的 AI 评测工作台，不是另造一个 Agent 框架或多租户云平台。中文不仅是翻译标签，还包括字段映射、费用确认、异常解释、来源标记、可复现比较和可讲述的演示路径。

| 路径 | 目标 | 验收边界 |
|---|---|---|
| A 首次配置 | 接入对象、导入数据集、确定评估器、执行、校准、设基线 | 未校准可执行，但不能设为新基线；运行前确认费用 |
| B 三步回归 | 历史 Run → 只改一个模型/Prompt/数据集版本 → 确认执行并对比 | 继承其他配置；同时列出变好和变差及独立维度 |
| C Prompt 优化 | 失败共因 → 改动 Diff → 人工确认 → 新版本回归 | 未确认不改；显示修复数与新增退化，不承诺模型调用零成本 |
| D 对象替换 | 新目标复用数据集、评估器和 Prompt 版本 | 同一可比较契约，缺失模态与字段必须阻断 |
| E 失败回流 | 将线上失败结果保存成样本，再做回归 | 保留来源和内容身份，不能用失败输出冒充标准答案 |

## 核心实体

`RunSpec = Target(s) × DatasetVersion × ScorerVersion(s) × EnvConfig × ExecConfig`。

- Prompt 独立版本化，由被测 Target 引用；Judge Prompt 是另一种用途，不能合并计数。
- `row_id` 基于规范化内容哈希；需先确定哪些业务字段进入身份、空值/图片引用规范与重复行政策。
- Run 创建后冻结引用版本、内容哈希和配置；不得因资源编辑而漂移。
- Baseline 指向一个具体 Run，不是一个分数，也不是 Evaluator 的 Active 发布状态。
- 数据与结果当前仍使用既有浏览器存储；ProjectRepository 是已实现的替换边界，不代表文件迁移完成。

## 交互层级

目标采用成熟工具的“项目上下文 → 业务模块 → 列表 → 详情 → 操作”层级。一级业务模块候选为评测集、评测对象、评估器、评测任务、Benchmark、运行监控、评测报告、Review、管理中心；页面 H1 对应当前模块，H2 对应配置/结果/历史，不再堆叠首页功能卡。

Langfuse 为具体源码和交互审计对象，Ant Design 已用于新增中文页面。尚未迁入 Langfuse 整站容器；未来每个候选组件必须先核对固定提交、许可、依赖树和保留的交互，再做独立小 PR。不得把重新绘图称作开源源码复用。

## MCP 与 Assistant

一期工具：`dataset.list`、`dataset.get`、`dataset.create_from_file`、`target.list`、`run.execute`、`run.status`、`report.get`、`report.diagnose`。当前两项只读工具不是这八项的别名，不能计为已经完成。

UI、API、MCP 共用领域 Action，但工具必须显式加入白名单。读取也需要数据范围与宿主外发提示；写入需预览和确认，执行需配额、幂等和取消；禁止外部 Agent 修改 Scorer 或 Baseline 后自评自判。stdio 已是可用 MCP 传输，不强制增开 HTTP 监听端口。

Assistant 一期四类场景：文件建数据集、配置并执行、查询导出、失败诊断。流程为意图 → 草案 → RunSpec/Diff 预览 → 确认 → 确定性 Action → 结果摘要。当前没有完整对话助手，也没有场景成功率实测。

## 冲突裁定

| 原要求或旧行为 | 本期裁定 | 后续验收 |
|---|---|---|
| 文件系统唯一真相 + SQLite 索引 | 按最新用户要求暂缓实现；保留替换接口 | 不新建数据库，不静默迁移/删除旧记录 |
| v5.0 加权总分、综合榜和风险阈值 | 新流程改为独立维度；旧历史保留并标注旧口径 | 单维度退化不能被平均掩盖；不重算原始历史 |
| 数据不出本机 + 各厂商 API | 本地存储不等于本地推理 | 联网模型必须明确数据外发和费用；无模型演示保持隔离 |
| Prompt 试错零成本、全自动回归 | 编辑文本不等于执行免费 | 用户确认或明确预授权的额度内才调用；不沿用历史运行授权 |
| 所有操作都封装 MCP | 共享 Action，不暴露任意视觉操作或任意路径 | 每工具独立 Schema、能力政策和审计 |
| 多人权限/组织角色 | 单用户工具本期明确不做 | 保留安全边界；工具调用范围不是多用户权限模型 |
| 全框架兼容 | 逐个版本和接入等级验证 | 固定 LangGraph/Mock 不代表任意 Agent 可用 |

## 验收与非目标

每个小 PR 都要有需求、代码、真实源文件测试、Mock 用户路径、异常路径、文档状态、Secret Scan、回滚说明及最终 head CI。允许先实现契约，但必须明确“契约”不等于端到端能力。

当前不新增数据库、队列、付费模型试验、完整多平台部署、任意代码沙箱、未确认业务数据导入或外部红队任务。十万级既有索引展示不构成 20GB 跑批 SLA；面试报告必须区分历史资料、合成夹具、本次无模型实验及未来计划。
