状态：Demo，待本轮测试与 CI 验收。面向产品经理解释执行链、失败恢复与并发，而非模型能力排行榜。

## 验收条件

- AC-01：从平台总览进入独立实验室；一页一个 H1，实验结果/详情为 H2，桌面及 390px 均可操作。
- AC-02：主动点击后采集顺序工作流、失败重试、并行协作三种执行方式。明确标为模拟决策；使用真实 OTel SDK，不访问外网/API，不修改项目数据库。
- AC-03：三条 Trace 共 14 个 Span、5 个工具步骤、1 个故障注入步骤、1 次重试；三个任务最终成功，但恢复的任务仍保留中间异常。父子链准确，耗时为根步骤墙钟时间，不累加并行耗时。
- AC-04：选择任务可看步骤树及异常位置，下载 JSON 能回读全部原始采集记录；tokens 和 cost 未测量用 null，不伪装为测得的零。
- AC-05：运行前不能下载，取消不发布半成品；新的完整运行产生新 ID；刷新清空实验并明确提示当前内存状态。
- AC-06：无严重/关键可访问性问题，源码测试与用户路径 E2E 通过；保留截图、失败日志和 CI 证据。
