# F-OBS-003 真实 LangGraph 的本地 Mock 节点观测

状态：已实现，本地门禁通过，[PR #51](https://github.com/boyuling-123/AI-API-workspace/pull/51) 最终 CI 待验。分支：`codex/feat-langgraph-observability`。前置：PR #50 已合并。

## 需求与边界

让产品经理看见真正由 Agent 框架调度的顺序、失败恢复路径，区别于已有手写模拟链。使用锁定的 LangGraph JS 1.4.14 / Core 1.2.9；节点只处理固定合成状态，不加载模型、真实数据、用户脚本或密钥。图由 StateGraph 编译，重试由框架 retryPolicy 执行，OTel 步骤由真实 callbacks 产生。

不新建后端存储、监听服务或模型评价。既有 Next API 仅启动一个短时子进程：固定可执行文件、固定入口、空白凭据环境、超时与取消清理。框架不进入浏览器包。不允许任意参数、路径或 prompt；不把此入口称为通用 Agent 执行器。

## 安全和准确性

- 子进程不继承父进程环境；关闭跟踪开关，导入框架前安装 fetch/HTTP/TCP/TLS/UDP 网络拒绝守卫。该守卫是固定实验的防误调用机制，不是恶意代码安全沙箱。
- 只导出固定名称、状态、时间、父子关系、尝试次数等白名单属性，不导出 graph input/output、错误堆栈或环境值。
- API 仅本机同源、固定专用请求头、空请求体、一次一个运行；请求取消/超时终止本次子进程，之前完成的页面结果保留。
- LangGraph/Core 的类型与实际 callback 参数顺序存在差异；适配实际锁定版本并用真实图执行回归，不能只 Mock 回调证明兼容。
- 两个成功任务中允许存在一个已恢复的失败步骤；token/成本仍为 null，模型调用为 0。结果只在当前页面，JSON 区分来源与版本。

## 验收

真实图产生两条调用链，顺序链 3 步、重试链 4 步；重试第一次失败、第二次恢复，根任务成功。源码测试检查父子关系、尝试次数、无外部网络、无环境继承、取消/并发/异常；Playwright 检查运行、选择、下载、错误恢复、窄屏、axe 和截图。旧的 3 组 Mock 实验保持不变。质量门禁与远端 CI 通过后再标记已验证。
