# 本地历史归档演示

## 如何打开

运行本地 Next 服务（例如 `npm run dev -- --hostname 127.0.0.1 --port 3002`），打开 `/history-demo`。总览页也有“打开历史归档演示（只读）”入口。这里不需要模型密钥，不会调用模型。

在被 Git 忽略的 `local-data/archive-source.json` 配置本机归档根目录：

```json
{
  "root": "/absolute/path/to/portable-archive",
  "provenance": "historical-unverified"
}
```

归档需为受支持的便携门户格式：`data/manifest.json` 描述 `recordShards`，分片位于 `data/records/records-NNNN.js`。读取器只解析固定包装中的 JSON，不执行 JS。任意文本、Excel 或其他 JS 不支持由此入口强行导入。

不复制归档，不新增数据库。迁移机器时携带源归档并重新配置路径，不把真实路径、配置或数据推到 GitHub。可通过进程环境变量 `EVAL_ARCHIVE_CONFIG` 指定另一份本机配置。测试会自动使用独立合成配置，不读取这份文件。

## 面试演示顺序

1. 展示总量、类别、原始 ID 去重数，解释“记录数”和“评测次数”不是一回事。
2. 查看旧清单与实际分片计数的偏差，说明数据治理与可追溯性。
3. 切换分片和类别，每页最多 50 条，说明这是分片内筛选而非全局检索。
4. 单条查看前确认隐私提示；默认隐藏正文、原名、路径，不加载远程图片。未收录内容不补造。
5. 下载只含统计与口径的 JSON；到 Agent 观测实验室运行明确标注的本地 Mock，区分历史归档与新采集的 Trace。

## 限制与故障

- 仅绑定回环地址，不暴露公网。这不是具有登录与多租户隔离的服务；同机进程仍可读取配置允许的数据。
- 初次逐片核对，之后复用计数快照；单页重读时校验分片哈希。源文件需保持不变；源文件变化后重启预览并重新核对。
- 单个文件上限 1MiB，单片最多 300 行，最多 1,000 片，索引总量上限 256MiB。超限拒绝，而非尝试把 20GB 内容装进浏览器。
- 默认不返回正文；确认后只返回当前记录中已收录的输入、输出和说明，常见密钥脱敏、每字段最多 6,000 字符，纯文本展示。不能保证所有业务或个人信息都被消除。
- 只展示证据哈希与行号，不打开证据文件；历史成功不代表本次验证成功，历史输出也不是标准答案。
- 不新增全局搜索、后台任务、自动评分、完整原始数据导出。本接口不是通用 MCP/Agent 执行动作；后续复用领域读取器时另做工具权限与输入契约。

未配置返回明确提示；非法来源/跨站访问拒绝；畸形、超量或变更归档阻断读取；错误信息不包含本机路径或原始文件内容。
