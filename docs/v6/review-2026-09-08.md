## 关键发现

### 1. 当前页面改版不是 v6 底座重构

根目录应用仍是 Next.js 14、React 18 和 IndexedDB。此前侧边栏、一级标题和页签改造可以作为交互原型与迁移参考，但与 PRD 指定的 EvalScope React/Vite Web、Python Service、文件真相源和 SQLite 索引不是同一架构。继续在旧页面扩功能会产生第二套事实模型，因此应冻结。

### 2. 指定 EvalScope 版本与 PRD 有实现偏差

上游 Web 使用 React 19、React Router 7、Vite 8、Vitest 4 和 Tailwind 4；现有入口采用顶部导航，路由集中在 Dashboard、Reports、Compare、Performance、Tasks、Benchmarks 和 Viewer，并没有 PRD 所需的 Target、Dataset、Evaluator 和 Run 产品页面。

上游 Service 实际使用 Flask，而不是 PRD 文本中的 FastAPI。现有 `invoke` 路径以阻塞方式启动任务，提供进度、停止和恢复接口，但尚无产品级 Action 层、不可变 RunSpec、统一确认、幂等键、项目域模型或可重建 SQLite 索引。后续文档和代码必须以真实 Flask 实现为起点；是否迁移 FastAPI 另立 ADR，不能在底座 PR 偷换框架。

### 3. EvalScope 已有大量可复用执行能力

源码中已有任务配置与执行、数据集和 Benchmark、指标/Judge、Agent 接入与 Trace，以及报告、对比、任务监控、Agent Trace 和 Judge Review 等组件。它们是高价值候选，但当前只能认定为“源码证据存在”；必须通过白底商品图最小业务试跑后，才能决定直接复用还是扩展适配。

### 4. 前端基线通过，但依赖安全尚未过门禁

固定提交的 Web 已完成以下只读基线验证：

| 命令 | 结果 |
| --- | --- |
| `npm ci` | 成功，安装 483 个包 |
| `npm test` | 63 个测试文件、462 项测试通过 |
| `npm run lint` | 通过 |
| `npm run drift` | 设计令牌、结构与中英文 locale 键一致性通过 |
| `npm run build` | 通过，2,861 个模块完成生产构建 |

`npm audit` 报告 7 项依赖风险，其中 6 项高危、1 项中危，涉及 React Router 及多个传递依赖。修复项必须在迁移分支中逐项升级并跑完整兼容性测试；不能在上游审计工作树中直接执行不可控的 `npm audit fix --force`。

### 5. Python 基线尚未完成

本机系统 Python 3.9.6 低于上游 `>=3.10` 要求。下一节点使用隔离的 Python 3.12 虚拟环境验证服务导入、无模型启动和选定单测；不得污染系统 Python，也不得执行需要模型、GPU 或外部密钥的测试。

## 迁移裁定

1. 当前仓库根应用冻结为 `v5 legacy`，只接受安全修复和迁移适配。
2. v6 开发必须从 EvalScope 固定提交创建可追溯 Fork 或同等保留上游历史的工作树，不能把 2,838 个文件手工复制后冒充 Fork。
3. 第一批代码不是重做首页，而是建立上游核验、Action 契约和白底商品图合成试跑。
4. 试跑通过后按“直接复用 / 扩展适配 / 自主补充 / 暂不支持”逐项裁定，再迁移中文侧边栏与对象页面。
5. Langfuse 继续作为交互与少量 MIT 代码来源；既有 vendoring 清单不代表整站迁移。

## 当前阻断项

- Python 3.12 服务基线与无付费最小试跑尚未完成。
- EvalScope Fork 的远端落点尚未建立。
- Action、领域对象、存储恢复仍是契约，尚无 v6 代码证据。
- 依赖安全审计未清零，不能把固定上游提交直接称为可发布版本。

这些阻断不会通过隐藏页面或营销文案绕过；完成后再更新底座能力核验表。
