# 存储迁移与恢复契约

## 分层

- **业务真相源**：项目目录中的 JSON、JSONL、Parquet 和 Blob 文件。
- **查询投影**：项目内 SQLite，保存列表、筛选、分页、统计和全文检索索引。
- **运行临时态**：锁、租约和缓存，可删除重建，不进入迁移包。
- **浏览器状态**：只保存 UI 偏好、最近项目和短期草稿，不保存大规模结果真值。

## 建议目录

```text
project-root/
  project.json
  targets/<target_id>/v0001.json
  datasets/<dataset_id>/<version_id>/
    manifest.json
    cases.jsonl
    blobs/<sha256>
  evaluators/<evaluator_id>/v0001.json
  runs/<run_id>/
    spec.json
    state.json
    events.jsonl
    items/<prefix>/<run_item_id>.json
    attempts/<run_item_id>.jsonl
    traces/<trace_id>.jsonl
    artifacts/<sha256>
  annotations/<scope_id>.jsonl
  audit/events.jsonl
  index/platform.sqlite
```

正式 Schema 以代码中的版本化定义为准；本文固定职责和恢复规则，不提前锁死分片大小。

## 写入规则

1. JSON 写入临时文件，`fsync` 后原子替换；JSONL 每条包含事件 ID、时间和校验摘要。
2. 大附件按 SHA-256 内容寻址，同内容只保存一次；业务对象只引用摘要和相对路径。
3. SQLite 更新失败不回滚已成功写入的业务文件，后台或显式 Action 重新投影。
4. 项目目录内禁止保存真实 Provider 密钥；只保存环境变量或系统钥匙串引用。
5. 所有导入路径规范化并限制在项目根目录，拒绝 `..`、绝对路径、符号链接逃逸和 Zip Slip。

## 20GB 级数据边界

- 导入采用流式解析和分块校验，不把完整文件读入内存或 URL。
- Web 只请求分页元数据、缩略图和用户展开的单条详情。
- 运行结果按 RunItem 分片，统计由增量投影生成。
- 下载使用服务端流式响应；可选择清单、失败项、抽样或完整包。
- 压力验收必须记录峰值 RSS、磁盘增长、吞吐和恢复时间，不能仅验证 10 万条空 Mock。

## SQLite 重建

`storage.rebuild_index` 必须：

1. 先只读扫描项目清单和 Schema 版本。
2. 输出待处理文件、损坏项、未知版本和预计时间，不直接覆盖现有索引。
3. 用户确认后构建新的临时数据库。
4. 对行数、对象摘要和关键外键执行一致性检查。
5. 原子替换索引，并保留可回滚的上一版索引直到验收完成。

删除 `index/platform.sqlite` 后，项目、版本、Run、评分、标注和审计记录必须从文件完整恢复；任务锁和 UI 偏好不要求恢复。

## v5 IndexedDB 迁移

迁移采用显式导出，不直接读取其他浏览器 origin：

1. v5 生成带 Schema 和摘要的只读迁移包。
2. v6 `storage.import_bundle` 先 dry-run，展示项目数、目标数、数据量、任务数、评价数、缺失附件和冲突。
3. 用户选择冲突策略并确认，不自动启动跑批或评价。
4. 导入写入新的对象版本，保留 `legacy_id` 和来源 Schema。
5. 比较对象计数、抽样内容摘要和运行矩阵后出具迁移报告。
6. v5 原数据不删除；回滚只移除本次新项目目录或恢复导入前索引。

## 迁移包

迁移包至少包含 `manifest.json`、相对路径文件、每文件 SHA-256、Schema 版本、导出工具版本和许可/来源元数据。默认不含密钥、日志中的凭证、浏览器偏好、缓存或临时锁。
