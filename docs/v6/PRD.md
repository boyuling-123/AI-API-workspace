## 产品定位

面向中文团队的本地优先 AI 模型评测工作台。它负责组织评测资产、编排模型或 Agent、保存可追溯结果、辅助校准 Judge，并通过统一 Action 暴露给平台助手和外部自动化。

平台不是完整复制 Langfuse，也不是把多个开源产品页面拼接到一起。EvalScope 提供执行和基础 Web 能力，Langfuse 提供信息架构与交互参考，本项目补齐中文产品层、版本治理、Action/MCP、可迁移存储和 Agent 管理。

## 不可变约束

1. EvalScope `c31f0f946c09bc087f856a017637ac157b5459a5` 是 v6 唯一代码基座。
2. 旧 Next.js 项目只迁移经过清单确认的业务能力，不作为新页面或新数据模型基座。
3. Langfuse 只复用许可清晰、依赖可隔离的 MIT 代码；禁止引入 `ee`、`web/src/ee`、`worker/src/ee`。
4. 所有可操作能力先定义 Action，再提供 Web、MCP、Agent 或外部 API 入口。
5. 不在 URL 中传完整数据；Deep Link 只携带 `project_id`、`draft_id`、`tab`、`mode` 等稳定标识。
6. 未确认字段映射、标准答案字段和评价模式时不得自动导入；未确认费用时不得启动跑批或 Judge。
7. 文件是业务真相源，SQLite 是可重建索引；删除数据库不能导致业务资产丢失。
8. 20GB 级数据不进入浏览器 IndexedDB；前端只分页读取元数据与结果片段。

## 核心业务闭环

1. 创建或导入版本化 Dataset。
2. 创建 TargetVersion，并通过显式预检验证连接和参数。
3. 创建 EvaluatorVersion，区分规则、代码、模型 Judge 和人工标注。
4. 由选择结果生成不可变 RunSpec，展示调用量、费用风险和缺失项。
5. 用户确认后提交 Run；任务支持排队、暂停、恢复、取消和失败项重跑。
6. 原始输出与 EvaluationRecord 分离，允许复用输出新增评估器而不重复调用被测模型。
7. 结果支持按 Case、Target、Evaluator、错误类型和版本下钻与对比。
8. Judge 校准、人工复核和发布记录只追加，不覆盖原始评分。

## 统一 Action 能力

P0 至少实现：

- 项目：创建、读取、列出、归档。
- 评测对象：创建版本、预检、读取版本。
- 数据集：解析、字段映射预览、校验、创建版本、分页读取。
- 评估器：创建版本、试跑、读取版本。
- 运行：预检、生成 RunSpec、提交、暂停、恢复、取消、定向重跑、查询状态。
- 结果：读取摘要、分页读取 RunItem、读取证据、导出。
- 存储：校验项目、重建索引、生成迁移包、导入迁移包。

P1 再把同一组 Action 以 MCP 暴露，并让全局助手通过工具调用完成平台操作。助手不得直接修改数据库或绕过确认门禁。

## 数据与版本

核心对象为 Project、Target/TargetVersion、Dataset/DatasetVersion/DatasetCase/CaseRevision、Evaluator/EvaluatorVersion、RunSpec、Run、RunItem、ExecutionAttempt、EvaluationRecord、Annotation、Trace/Span、ArtifactVersion、OptimizationTask。

所有正式执行都绑定不可变版本。草稿可修改；一旦被 RunSpec 引用，任何变化必须生成新版本。任务继续沿用原 RunSpec，不能偷偷读取最新草稿。

## 完成定义

每项能力必须同时具备：验收条件、真实源码测试、异常路径、无真实密钥、可回滚、文档状态更新以及截图或 Trace 证据。仅完成页面、接口类型、Mock 或文档均不能标记为已验证。
