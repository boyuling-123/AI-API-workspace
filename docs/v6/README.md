# AI 模型评测工作台 v6.0

## 当前结论

v6.0 不是对现有 Next.js 首页继续换皮，而是一次有迁移边界的底座重构：

- **唯一代码基座**：EvalScope 固定提交 `c31f0f946c09bc087f856a017637ac157b5459a5`。
- **产品交互参考**：Langfuse 的信息架构、实验与 Trace 交互；不复制其企业版目录，也不引入第二套执行真相源。
- **旧系统定位**：仓库根目录的 Next.js 应用只作为 v5 能力迁移源，禁止继续扩展成另一套 v6 UI 或数据模型。
- **产品边界**：本地优先、中文友好、可迁移、Agent 可操作；文件是业务真相源，SQLite 只做可重建索引。
- **安全边界**：Mock 和合成数据优先；未经单独确认不调用付费模型、不启动 AI 评价、不导入用户真实大数据。

## 状态口径

底座能力只使用以下四种处置结论：

| 状态 | 定义 |
| --- | --- |
| `直接复用` | 上游能力已通过真实最小业务试跑，可原样进入产品链路 |
| `扩展适配` | 上游有可信实现，但需中文、Action、版本或本地存储适配 |
| `自主补充` | 上游不存在或不满足产品契约，需要本项目实现 |
| `暂不支持` | 当前阶段明确不交付，页面必须隐藏而非放空壳 |

“源码中找到”不等于“直接复用”。只有代码证据、测试证据和验收证据同时存在，才能把业务能力写成已验证。

## 第一条业务试跑

底座迁移的第一个功能 PR 只验证一条端到端链路：白底商品图任务。它必须完成数据导入、目标执行、独立评分、逐条详情、失败隔离和结果恢复，不使用真实用户数据或付费服务。该试跑通过前，不批量迁移旧页面。

## 架构决策

1. 先核验再迁移，不从截图或旧 UI 倒推数据模型。
2. Web、MCP、Agent 和外部 API 只能调用统一 Action 层，不能各自直连执行引擎。
3. RunSpec 创建后不可变；继续、重跑和新增评价均创建新 Run 或新 EvaluationRecord。
4. 文件系统保存可迁移业务资产，SQLite 保存可删除重建的查询索引。
5. 页面只展示已实现能力；P1/P2/P3 页面未到阶段时从导航隐藏。
