# 领域对象与版本关系说明

## 设计原则

- 身份与内容版本分离：稳定对象 ID 用于引用，版本 ID 冻结执行内容。
- 草稿可变、已发布版本不可变；任何正式 Run 只引用版本 ID。
- 原始执行与评价分离：一个 RunItem 可以拥有多个 EvaluationRecord。
- 人工复核只追加覆盖层，不修改模型原始输出或 Judge 原始结果。
- Trace、附件和导出物使用内容摘要校验，SQLite 只保存查询投影。

## 对象目录

| 对象 | 作用 | 版本规则 |
| --- | --- | --- |
| `Project` | 工作空间、默认配置和资源边界 | 配置变更记录审计事件 |
| `Target` | 模型、Agent、算法或工作流稳定身份 | 每次可执行配置变化生成 `TargetVersion` |
| `TargetVersion` | Provider、模型名、参数、输入输出 Schema | 被 RunSpec 引用后不可变 |
| `Dataset` | 数据集稳定身份 | 内容或 Schema 变化生成 `DatasetVersion` |
| `DatasetVersion` | 字段 Schema、Case 集和资产摘要 | 正式执行后不可变 |
| `DatasetCase` | 跨版本可追踪的业务样本身份 | 修订内容生成 `CaseRevision` |
| `CaseRevision` | 某次输入、标准答案、附件和元数据 | 内容寻址，不原地覆盖 |
| `Evaluator` | 评估器稳定身份 | 定义变化生成 `EvaluatorVersion` |
| `EvaluatorVersion` | 指标、Rubric、Prompt、Judge、阈值 | 校准与发布均引用固定版本 |
| `RunSpec` | 本次执行的完整冻结配置 | 创建后永久不可变 |
| `Run` | RunSpec 的一次执行实例 | 状态变化写事件，不改 RunSpec |
| `RunItem` | 单个 Case × Target 的逻辑结果 | 可有多次 `ExecutionAttempt` |
| `ExecutionAttempt` | 一次真实请求、响应、耗时和错误 | 只追加，不覆盖失败历史 |
| `EvaluationRecord` | EvaluatorVersion 对 RunItem 的一次评分 | 与原始输出分开保存，只追加 |
| `Annotation` | 人工标签、复核和说明 | 版本链只追加，不覆盖原 Judge |
| `Trace` / `Span` | 一次执行的步骤、工具和父子关系 | 与 RunItem、Attempt 关联 |
| `ArtifactVersion` | 图片、日志、报告等外部资产 | 内容摘要作为完整性证据 |
| `OptimizationTask` | Prompt/Skill 优化任务 | P2 前不进入导航 |

## 关系

```text
Project
  ├─ Target ─ TargetVersion ─┐
  ├─ Dataset ─ DatasetVersion ─ DatasetCase ─ CaseRevision
  ├─ Evaluator ─ EvaluatorVersion ─┐
  └─ RunSpec ──────────────────────┴─ Run
                                      └─ RunItem
                                          ├─ ExecutionAttempt
                                          ├─ EvaluationRecord
                                          ├─ Annotation
                                          ├─ Trace ─ Span
                                          └─ ArtifactVersion
```

## 标识与指纹

| 字段 | 规则 |
| --- | --- |
| `id` | 稳定、不可复用；推荐 `<kind>_<uuidv7>` |
| `version` | 对同一稳定对象单调递增的人类可读序号 |
| `content_hash` | 对规范化 JSON 或文件内容计算 SHA-256 |
| `created_at` | UTC RFC 3339，由服务端或本地服务写入 |
| `created_by` | 本地用户、Agent 或外部调用方的稳定标识 |
| `schema_version` | 每类对象独立演进，不用应用版本替代 |

规范化 JSON 必须固定键序、编码和空值语义。凭证只保存引用名，不进入指纹、导出或日志。

## RunSpec 最小内容

RunSpec 必须冻结项目、DatasetVersion、CaseRevision 集、TargetVersion 集、EvaluatorVersion 集、执行参数、并发/QPS/超时/重试、缺失策略、内容模式、随机种子、创建人和确认摘要。

暂停后继续必须使用同一个 RunSpec。更改目标、样本、Evaluator 或执行策略时创建新 RunSpec 和新 Run，并用 `source_run_id` 表达血缘。

## 一致性约束

1. RunItem 唯一键为 `run_id + case_revision_id + target_version_id`。
2. 幂等重试不能创建重复 RunItem；新的业务重跑必须创建新 Run。
3. EvaluationRecord 必须引用真实存在且终态可评价的 RunItem。
4. DatasetVersion 删除采用归档，不得破坏历史 RunSpec 引用。
5. 任何损坏或缺失的内容摘要必须显式告警，禁止静默回退到最新版本。
